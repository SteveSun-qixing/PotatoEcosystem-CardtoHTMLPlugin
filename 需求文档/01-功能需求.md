# CardtoHTMLPlugin 功能需求文档

## 模块定位

CardtoHTMLPlugin 是薯片生态文件转换系统的核心插件，负责将卡片文件转换为完整的 HTML 网页。作为转换系统的基础模块，CardtoImagePlugin 和 CardtoPDFPlugin 都依赖本模块的 HTML 输出进行二次转换。

## 核心功能

### 卡片解析

插件接收卡片文件路径或已解包的卡片数据作为输入。首先读取卡片的 metadata.yaml 获取卡片基本信息，包括名称、版本、创建时间、主题配置等。然后读取 structure.yaml 获取卡片的层级结构，了解包含哪些基础卡片以及它们的排列顺序。

解析过程中需要验证卡片格式的正确性。如果 metadata.yaml 或 structure.yaml 缺失或格式错误，返回明确的错误信息。如果基础卡片的配置文件缺失，记录警告但继续处理其他卡片。

### 基础卡片渲染

遍历 structure.yaml 中定义的所有基础卡片，为每个基础卡片生成独立的 HTML 文件。每个基础卡片的 HTML 文件是完整的网页，包含该卡片的渲染内容和必要的样式。

基础卡片的渲染代码来自对应的基础卡片插件。每种基础卡片类型（富文本、图片、视频等）都有对应的前端渲染组件，插件需要获取这些渲染代码并嵌入到生成的 HTML 中。渲染组件的获取通过薯片 SDK 的插件 API 完成。

如果某种基础卡片类型没有对应的渲染插件，生成一个占位 HTML，显示卡片类型和提示信息。

### 主入口生成

生成主入口文件 index.html，这是转换结果的入口页面。主入口页面使用 iframe 嵌套的方式组织所有基础卡片，按照 structure.yaml 定义的顺序排列。每个 iframe 加载对应基础卡片的 HTML 文件。

主入口页面包含整体的页面框架、布局样式和主题样式。页面框架定义卡片容器的布局方式，iframe 的尺寸和间距。布局样式确保各个基础卡片按正确的顺序和方式排列。

### 主题应用

读取卡片 metadata.yaml 中的主题配置，通过薯片 SDK 的主题 API 获取对应主题包的样式定义。将主题的 CSS 变量和样式规则提取出来，生成 theme.css 文件。

主入口页面和每个基础卡片的 HTML 都需要引用 theme.css。主题样式通过 CSS 变量系统应用，不同层级的组件可以使用相同的变量名获取一致的视觉效果。

如果指定的主题不存在，使用默认主题。如果没有配置主题，也使用默认主题。

### 资源处理

遍历卡片中的所有资源引用，将资源文件复制到输出目录的 assets 文件夹中。资源包括图片、视频、音频、字体等文件。资源在 HTML 中的引用路径需要更新为相对于输出目录的路径。

对于内部资源（相对路径引用卡片内的文件），直接复制到 assets 目录。对于外部资源（绝对路径或网络 URL），根据配置决定是否下载并内嵌，或保留原始引用。默认情况下，本地外部资源复制到 assets 目录，网络资源保留 URL 引用。

### 输出组织

转换结果输出为一个完整的目录结构。根目录包含 index.html 主入口文件和 theme.css 主题样式文件。cards 子目录存放所有基础卡片的 HTML 文件，文件名使用基础卡片的 ID。assets 子目录存放所有资源文件，按类型分为 images、videos、audios 等子目录。

如果指定了输出路径，在该路径创建目录并写入文件。如果没有指定输出路径，返回包含所有文件内容的数据结构，由调用方决定如何处理。

## 接口设计

### 插件注册

插件启动时向公共基础层的 FileConverter 模块注册自己。注册信息包括插件 ID、名称、版本、支持的源文件类型（.card）、目标文件类型（HTML 目录）、转换选项定义。

### 转换接口

插件提供标准的转换接口，接收转换源和转换选项，返回转换结果。转换源可以是卡片文件路径或已解包的卡片数据。转换选项包括输出路径、是否包含资源、主题 ID、资源处理策略等。

转换结果包括是否成功、输出路径或数据、错误信息、转换统计（耗时、输入大小、输出大小）。

### 进度回调

对于包含大量资源的卡片，转换过程可能较长。插件支持进度回调，在转换的关键节点报告进度。进度信息包括当前阶段（解析、渲染、资源处理、写入）、完成百分比、当前处理的文件名。

## 错误处理

定义明确的错误类型和错误码。卡片格式错误、资源缺失、渲染失败、写入失败等情况都有对应的错误码。错误信息包含足够的上下文，便于调用方定位问题。

部分错误可以降级处理。单个基础卡片渲染失败不影响其他卡片，生成占位内容并继续。单个资源文件缺失记录警告但继续处理。只有关键错误（如卡片格式完全无效）才中止转换。

## 性能考虑

对于大型卡片（包含大量基础卡片或大量资源），转换过程需要优化。基础卡片的渲染可以并行处理。资源文件的复制使用流式处理，避免内存占用过高。支持增量转换，如果卡片内容没有变化，跳过已生成的文件。

## 依赖关系

插件依赖薯片 SDK 获取卡片数据、插件渲染代码、主题样式。依赖公共基础层的 ZIPProcessor 解析卡片文件，依赖 DataSerializer 处理 YAML 配置文件。所有依赖都通过微内核路由调用，不直接引用。
